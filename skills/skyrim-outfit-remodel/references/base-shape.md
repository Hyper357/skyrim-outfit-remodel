# 零滑块基形、体重与隐藏修正

## 先分清四种状态

“所有滑块为 0”是参考体系的基形，不保证每个围度最小；`_0.nif` 是低体重输出，也不等于所有 sliders=0。另有“按 OSP 默认值加载”和“套个人 preset”两种状态；隐藏 slider 也有默认值，需一并记录。

当裸 ShapeData / Add Project 后过粗，但应用 preset 或默认值后正确，查原始坐标、隐藏非零默认修正、实际 UI 值与供体基形。不要先全局缩放，也不要直接把个人 preset 设为 base。[作者的项目基形要求](https://github.com/ousnius/BodySlide-and-Outfit-Studio/wiki/Creating-a-BodySlide-project)

## 固定修正依赖

本案例将靴筒收紧放在 `FitJ3Clearance_v7` 中，hidden=true、small=big=100。原始基形未含此收紧；归零或转入另一项目时若丢失隐藏修正，靴筒便偏宽。数据集/索引合法和个人 preset 构建成功都没有覆盖这个问题。

位置 morph 的普通线性状态为 `V = B + Σ(s_i D_i)`。若一项是**设计上始终应当存在**的固定修正 cD，可采用 `B' = B + cD` 并移除该项，其他 D 保持；由此避免重复应用并保留原 preset 的结果。small=big 只是筛选线索，必须另确认其语义、外部依赖及所有相关项目。隐藏默认不同、zap、invert、clamp、UV morph 和条件变形不能直接用这个步骤。

## 可执行修复顺序

1. 找真实 winner，保存源 NIF/OSD/OSP、分组和预设。记录 raw zero、default、目标 preset 两体重端的基线。
2. 明确选定固定修正；显式将全部可见/其他隐藏项置 0，仅此修正置 c。用隔离 BodySlide 构建得到候选基形，不把个人 preset 整体烘焙。
3. 候选 NIF 必须与 `B+cD` 按原索引对应，且 UV、faces、骨名/权重、绑定变换、分区与材质保持。检查法线、切线和包围体；未知工具的全量重存先做零改动往返验证。
4. 用候选更新**隔离副本**的 ShapeData；从所有关联 OSP 移除此固定项，核实无其他引用后再移除其 OSD dataset。其余可见形态和体重相关修正保留。不要留下会把同一修正再次叠加的 helper。
5. 实际构建原 preset 的 `_0/_1/TRI`，逐点对照修复前结果；容差按坐标单位与输出量化决定，并验证正常数值/绑定/资源引用。再查零滑块构建等于新裸基形，不能只证明个人 preset 仍正确。
6. 用参考零位身体/内层查围度与间隙，补零位视觉与动作验收。静态/构建通过不能写成游戏通过。
7. 用户要求合并到原模组时，同步完整 source、输出和材质资源；清除重复项目与覆盖链。补丁是否冗余要比较具体记录。只删除已核验、已备份的冗余目录，保留装备身份与输出路径。

`audit_bodyslide.py` 报告 `constant_hidden_geometry` 和 warning，提示裸基形依赖隐藏默认修正；这是调查入口，**不自动判为错误或执行烘焙**。当前检测排除常见 zap/invert/clamp/UV 属性，不能替代完整版本语义研究。

交接中同时记录四种状态、修正系数/数据集、被更新的项目、前后误差、零位与 preset 的证据，以及仍 pending 的 GUI/游戏验收。
