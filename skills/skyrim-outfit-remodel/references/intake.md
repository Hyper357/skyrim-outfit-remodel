# 接收工程与基线

## 输入与实际生效链

记录指定底稿、参考优先级、游戏分支、身体/手脚/头部供体、骨架与物理依赖、目标 preset/体重范围、穿戴层、性能预算、可改与保护区域。已有指定直接采用；缺项先查工程，只有影响决定的缺项才询问。

原穿戴姿态包括足部朝向、踮脚程度、跟高抬升、装备与身体相对位置；不等于把动画截图烘焙进 bind pose。

1. 查 ARMO → ARMA：性别、种族对应的穿戴模型；另查第一人称和掉落/预览模型。
2. 查 NIF shape、材质/纹理、额外数据、分区及插件 TXST 替换；区分 ShapeData 源与运行时 meshes。
3. 在启用的 MO2 VFS 查 winner：原模组、BodySlide Output、生成器、overwrite、档案。可用时优先 houseCARL；否则用 MO2 信息面板和 VFS 内工具。磁盘文件存在不代表生效。
4. 备份触及文件并记录哈希、变更目标。插件修改使用现有记录工具，核对字段差异，不手改 ESP/ESM 二进制。

## 修改路线

| 路线 | 条件 | 实施 |
|---|---|---|
| 坐标微调 | 原拓扑/UV/权重健康 | 保持索引、保护其他部位；验证旧 slider 对新基形是否仍适合 |
| 表面修复 | UV/法线/材质局部问题 | 只改证据指向的数据层；源和运行时同步 |
| 重拓扑 | 面流/密度无法支撑造型 | 留原供体；最终网格稳定后映射 UV/权重并重建形态 |
| 绑定/物理修复 | 不跟随关节、骨链异常 | 保留原结构，先查骨架/绑定/配置再修局部权重 |

同顶点数但顺序变化也使旧索引失效。不能按旧行号复制数据。拓扑稳定也不证明旧 slider 的 delta 适合新轮廓。

## 基线报告

- 文件哈希、工具版本/构建号、源/winner 路径、shape 名和角色。
- 原/导出网格数量、UV 层、法线、材质、骨名、影响数、权重和、绑定变换。
- 形态、隐藏/反向/zap slider、体重输出、BODYTRI、分区/插槽。
- 同机位/投影/光照正侧背与局部预览；必要时零改动往返实验。
- 已经能成功重建/穿戴的状态及未验证项。

性能按整套组合评估三角形、拆点后顶点、shape/材质数量、贴图/mip、骨骼与物理成本。面数预算按使用场景决定，不能给所有装备套一个固定阈值。
