# 三个交接走查示例

以下为训练 agent 判断修改路线的场景，不是这些装备已完成游戏验收的声明。每次替换为实际文件、版本与证据；不存在的输入保持 pending。

## 手套：重新捏指形、需要重拓扑、保留配套材质

1. 找实际 ARMA 手套路径、MO2 winner、配套胶衣材质，以及正确身体体系的手/手指参考。保存原手套的源 BS 工程、所有自定义 slider、骨名、分区和 shape 对应。
2. 判断重拓扑使旧索引失效，选择 intake 的重拓扑路线；原手套留作 UV/材质/自定义形态供体，不能直接把旧 TRI 改名给新网格。
3. 在原 bind/穿戴姿态下捏形；手腕与袖口贴合，分手指检查指蹼和掌心。保护先前确认的区域，用空间映射/轮廓偏差证据，不能沿用旧索引 allow map。
4. UV 按手指和掌背分区，排除另一根手指的近邻投射；用棋盘格判断拉伸，再转移/烘焙目标贴图。材质查实际 TXST/cubemap/mask，不以 BS 中同样黑亮为充分证据。
5. 以正确手部供体转移骨权重，单指、拇指、握拳和腕屈伸验收；衣袖供体不能代替手指骨。SMP 组如存在单独保护。
6. 用目标带 slider reference 重建新网格的形态；恢复自定义项，检查分组与 preset，实际构建低高体重与 TRI。固定三角化/拆点/shape 名后查已知 slider 的真实输出。
7. 审计源和输出，并做材质与触发 CTD 的穿戴/物品预览回归。缺游戏环境时，HANDOFF 的 runtime 保持 pending，交付完整 source、构建命令和下一步动作。

## 领口：静态有缝，转头时不跟随

1. 保持拓扑先排查：静态间隙来自基形/preset 还是动画绑定？领口实际是否有颈骨权重、bind transform 是否匹配？同一身体、同一骨架做单关节转头对照。
2. 仅几何缝隙则局部调整坐标并保护其他区；动作不跟随则在下胸肩与上颈部之间修权重渐变。Head 的参与由领口高度/动作决定，不能整圈直接绑头。
3. 索引不变也重新测试旧 slider 是否适配新基形。不要清空整件权重或重建所有形态来解决一个局部领口问题。
4. compare_mesh 的 allow map **只允许坐标变化**；本次计划修改权重时，它报告 weights_changed 属预期差异，要另给权重区域 diff 和导出审计，不能把失败报告改成全通过。
5. 低/仰头、左右转头、抬肩与目标体重/preset 下查穿插。修了静态缝隙但未测动作时，只能记静态部分通过。

## 硬甲或带 SMP 裙摆：整套装备的局部改形

1. 分辨刚板、软连接、人体蒙皮、物理骨链和碰撞层。原来不参与 slider 的刚板不必强行全局 conform。
2. 不整件 shrinkwrap/Copy Bone Weights，避免硬板弯曲与物理权重丢失；用所属层和区域供体处理。
3. 裙摆/披风按 physics.md 保全骨链、extra data、XML 与碰撞引用。当前技能没有其完整游戏通过案例，不能套鞋靴的静态标准验收物理。
4. 头部覆盖物若涉及面部动画/表情 TRI，转入匹配头部工具的专项调研；本技能 BodySlide TRIP reader 不处理头部 TRI。
5. 按实际涉及数据层安排验证与交付；未改插件身份也要核对部署路径/winner，确保读取的是本次资源。
