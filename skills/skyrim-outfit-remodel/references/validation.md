# 阶段验收与 agent 交接

## 状态契约

每项用 `pass / fail / pending / not_applicable`，并给证据路径、工具/输入版本和理由。缺工具/未执行是 pending。脚本退出 0 只覆盖其报告的检查；不能自动推出视觉或游戏通过。

| 验收 | 证据 |
|---|---|
| 造型 | 固定投影/机位的主视图与局部，对照参考；用户确认区域单独列出 |
| 网格/UV | 实际源/导出统计、退化/异常、UV 棋盘格与接缝、烘焙检查 |
| 权重/绑定 | 数值、骨名/绑定/分区、相应关节动作的复现与截图 |
| BS | OSP/NIF/OSD 引用、source/preset 哈希、实际隔离构建日志、低/中/高与 slider 组合 |
| 形态索引 | 最终输出的 shape/点序与 morph 对应；范围检查加实际已知 slider 变形 |
| 材质/资源 | NIF/TXST/生成器/SMP/BODYTRI 依赖与 winner；目标光照下视觉 |
| 游戏 | 穿戴、卸下、物品预览、第一/第三人称适用视角、动作、体重、重新载入；必要时最新 crash log |
| 回退/交接 | 当前工程与配套资源、重建命令/工具版本/预设/依赖、变更清单和已识别回退点 |

标准输出目录可按工程调整：source、references、build-inputs、staging、evidence、handoff。不要建立没有用途的空目录。

## 交接最小内容

当前唯一继续修改的工程及哈希；实际部署源/输出/winner；目标身体和 preset；已封账区域；修改路线；UV/权重/形态供体与映射；最终导出规则；重建命令；验证状态；未决问题；下一步具体输入和动作；研究 URL；回退范围。

若未完成游戏测试，可以交付模型/技能但必须标记 runtime pending。本技能本身通过代码/文档/只读真实资源测试，也不能证明未来所有装备转换成功。

## 发布技能仓库

仅提交通用说明、脚本、合成测试与去本机化的案例摘要。忽略模型/贴图/工具 DLL/存档/日志原文/包含实际几何的快照/个人配置。选择明确文件列表提交，检查暂存区与仓库体积；确认公开范围后推送。仓库 CI 只能做合成/结构测试，不能模拟 Skyrim 游戏验收。
