# 材质一致性与部署

## 材质按实际游戏链检查

1. 找当前生效的配套装备作为供体，记录 shape shader 类型/flags/参数、纹理槽、颜色/透明度、cubemap、反射遮罩和法线 alpha。
2. 检查插件 TXST/Alternate Textures 和生成器输出。BodySlide 预览相似不证明游戏走同一材质。[PyNifly shaders](https://github.com/BadDogSkyrim/PyNifly/wiki/Shaders)
3. 同套材质匹配不仅复制 gloss/specular；比较目标区域的 diffuse、mask、normal、alpha 和实际 cubemap。取供体对应的袖口/腿部区域，不盲用整张贴图中位数。
4. 新 UV 不直接套旧贴图。保留原色彩/透明/金属效果，除非用户要求改色或风格。传统 shader 与 PBR 配方不能互相套用通道；生成器资料按版本调研。
5. 核对 shader 类型与条件数据/flags 相容。处理结构问题用理解该格式的工具，不根据某个样本长度对所有 NIF 固定偏移补字节。
6. 材质修改前后比较几何、UV、骨表、权重、分区及 extra data。不需要改蒙皮时，验证它确实未变；零改动往返失败的工具版本不进入原文件修改流程。

## 资源闭合

从穿戴/第一人称/掉落 NIF、TXST、BODYTRI、SMP XML、生成器配置递归收集依赖。逐项记录：包内文件、已声明依赖提供、未解决。检查大小写/相对路径、DDS 格式与 mip。目录存在不算资源闭合；生成器实际胜出结果也在范围内。

## 部署步骤

- 默认在隔离模组/输出目录测试。用户已明确要求替换原模组时，按已有授权备份并执行，无需重复确认同一操作。
- 将 ShapeData/SliderSets/所需分组与预设依赖、运行时 meshes/TRI/textures/配置一起同步。
- 保持 FormKey/装备身份/插槽/种族与性别映射；仅路径需改时通过记录工具修改精确字段并对照差异。预览模型单独核对。
- 生成器覆盖目标时查源配置与重新生成流程，不把生成目录一次修改当可持续修复。
- 重新核验实际 winner，再从交付的源构建；构建后再查 winner，避免 BodySlide 写到另一目录。
- 重启/重新载入受影响资源后做游戏测试，并保留可识别回退点。不要用游戏里缓存的旧装备判断本轮文件。

不自动改 INI/加载顺序、不批量清备份。发布技能仅包含自写流程与脚本；第三方模型、贴图、工具二进制保持外部依赖，另行发布模型需独立确定其范围。
